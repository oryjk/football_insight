# 战术板私密草稿与显式发布

用户已确认：底部保持一行，左侧重置/分享，右侧存草稿/发布，均带线性图标和文字；发布使用红色主按钮，发布过后显示“更新发布”。

## 行为

- 私密草稿允许 0–11 人，登录后可存云端并跨设备恢复；游客保留本机草稿，明确触发登录保存后才移交给登录账号。
- 发布必须满 11 人，先显示已有居中双按钮确认框；发布成功才进入球队榜单。再次发布沿用公开记录、分享码、点赞和创建时间。
- 编辑和存草稿不改变已发布内容。分享只读取公开快照，有未发布修改时提示先发布，不得通过分享隐式写入。
- 重置仍需确认，仅恢复当前阵型默认站位，保留球员。页面状态区区分草稿已保存、有未发布改动、已发布。
- 保持一屏完成操作；图标源文件为 SVG，运行时使用透明 PNG，符合现有小程序约定。

## 数据与兼容

- 新增私密草稿表 `f_i_lineup_drafts`，每用户每球队一条；迁移将既有个人阵容复制为初始草稿。既有 `f_i_lineups` 继续承载公开快照和点赞关联。
- 新增 GET `/lineups/me/{team_id}/editor` 返回 `{lineup,draft}`；`lineup` 只返回满 11 人的公开快照。
- 新增 PUT `/lineups/me/{team_id}/draft` 返回 `{draft}`；PUT `/lineups/me/{team_id}/publish` 返回 `{lineup,draft}`；写入参数均为 `{formation,slots}`。
- 新发布在同一 repository command 内原子更新公开快照和私密草稿。旧 GET/PUT 保留既有语义，旧 PUT 也同步私密草稿，保证旧体验版继续可用。
- 授权和满员规则留在应用层，Web 只映射 DTO，SQL 和事务留在持久化 adapter；前端展示组件只收 props/emit。
- 本机未同步草稿按账号隔离；新响应不得清除保存期间的新编辑，切队/切账号后的旧响应不得改变当前状态。旧 autosave 登录标记只可恢复私密草稿，不自动发布。

## 验收

覆盖草稿隐私、未满员拒绝发布、存草稿不改变公开/点赞、更新发布保留身份、跨账号与迟到响应；以独立临时 PostgreSQL 测试实际迁移和事务，不写生产测试数据。前端验证小屏幕、取消、分享无写入、登录恢复意图及双端构建。
