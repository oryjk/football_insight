# 赛前胜平负倾向（数据倾向）设计

日期：2026-10-18
状态：待实现。研究与回测已完成，本文档把结论固化为产品与工程规格。

## 背景与目的

产品要深耕成都蓉城球迷社区。非开票期、非主场的空档里，用户缺少回来的理由。
赛前给出每场比赛的「数据倾向」（主胜/平/客胜概率），赛后复盘「模型对不对、为什么」，
形成固定的回访节奏，也为抖音内容提供素材。

它的价值在于**用我们自己的比赛数据做出诚实、可验证的分析**，而不是做预测噱头。

## 目标

1. 对每场未开赛的比赛，给出主胜/平/客胜概率。τ 保留用于模型校准，不在界面增加把握度解释。
2. 开赛前的预测一旦开赛即冻结，赛后自动计分，公开累计战绩（对比基线）。
3. 在小程序洞察页展示（首页仅轻量入口），措辞克制、可解释。

## 非目标

- 不使用任何博彩公司赔率、盘口数据，不作为输入，也不作为对照，不引入相关字段。
- 不给「推荐比分」「稳」「必」等承诺性结论，不做投注引导。
- 不做球员级、阵容、伤停预测（数据不可得）。
- 首版不做泊松模型、不做技术统计特征（见「未纳入」）。
- 不做付费功能，不加会员门槛（价值在留存和传播）。

## 反目标（出现即算失败）

- 开赛后修改已发布的预测，或战绩统计里混入事后修改的预测。
- 页面把概率当作确定结论，或使用「赔率、盘口、投注、推荐、稳、必中」等词。
- 预测计算放进 Rust 后端或小程序前端现算。
- 因预测生成失败导致原有同步（sync）失败或回滚。

## 已验证的结论（来自回测，决定了本设计）

数据：新浪接口可取 2014–2026 共 13 个赛季约 3000 场比分；球队必须按 `team_id` 而非名称（球队多次改名）。
2020、2021 为疫情赛会制，近乎中立场地，需当作无主场优势。

回测方法：滚动前向，每场只用此前数据；调参只用目标赛季之前的三个赛季；
2019–2026 共 1823 场样本外（剔除 2020–21 后 1487 场）。指标为 RPS（越低越好）、对数损失、命中率。

| 模型（剔除 2020–21，1487 场） | RPS | 命中率 |
|---|---|---|
| 基线：此前主平客历史频率 | 0.2299 | 45.4% |
| Elo，固定参数（2016–2018 调出） | 0.2014 | 53.3% |
| V1：Elo，每赛季用此前三个赛季滚动调参 | 0.1989 | 54.5% |
| **V2：V1 加自适应收缩（生产模型）** | **0.1988** | **54.5%** |
| 泊松（简化 Dixon-Coles） | 0.1994 | 53.9% |

- 相对基线显著更好（RPS 差 -0.031，95% 置信区间 [-0.0386, -0.0235]）。
- V1、V2 相对固定参数 Elo 的提升**不显著**；V2 的价值在于校准和「把握度」，不在命中率。
- 校准：V2 各概率区间的预测值与实际频率基本贴近（例如预测 0.067 实际 0.070，预测 0.545 实际 0.515）。
- **2026 赛季是异常年**：球队场均积分的离散度为历年最低（0.306），而模型赛季初评分的离散度为历年最高（124），
  模型过度自信；V2 自动学到收缩系数 τ≈0.64，但 2026 年相对基线仍无可证实的优势（RPS 0.2209 对 0.2255，
  差异的置信区间跨过 0）。**产品必须据此降低预期，不得宣称「准」。**
- 完整研究脚本与诊断见 `sina_csl_scraper/research/match_outlook/`，生产实现必须复现上述数字（见验收标准）。

## 模型规格（V2）

Elo 加有序逻辑回归映射成三类概率，加自适应收缩。输入只有比分、主客队 `team_id`、日期时间、是否中立场地。

**评分与概率**

- **任何球队首次出现时，初始评分一律取 `newstart`**（包括回放起点 2014 年的全部球队，也包括之后的升班马）。
  1500 **不是**初始评分，只是赛季间回归的锚点。（此前版本写作「所有球队初始评分 1500」，与研究脚本不符，以脚本为准。）
- 每个新赛季开始时，所有已有球队评分向 1500 回归：`R = reg * R + (1 - reg) * 1500`。
- 预测：`x = (R_home + H * 非中立 - R_away) / s`；`τ` 为自适应收缩系数；
  `P(主胜) = σ(τx - c)`，`P(客胜) = σ(-τx - c)`，`P(平) = 1 - P(主胜) - P(客胜)`，再归一化。
- 更新：`E = P(主胜) + 0.5 * P(平)`，实际得分 S 为 1 / 0.5 / 0，
  `delta = K * (1 + |净胜球|)^gexp * (S - E)`，主队加 delta，客队减 delta。
  更新用的 `E` 取自**已应用 τ 的**概率（与回测脚本一致）。

**滚动调参（每个目标赛季一次）**

- 网格：K ∈ {10,20,30,45}，H ∈ {30,60,90}，s ∈ {150,200,250}，c ∈ {0.3,0.5,0.7}，
  gexp ∈ {0,0.5,1.0}，reg ∈ {0.4,0.6,0.8,1.0}，newstart ∈ {1400,1450,1500}。
- 对每组参数从 2014 年起连续回放全部历史，得到各赛季平均 RPS；目标赛季 Y 选取
  **Y-3、Y-2、Y-1 三个赛季（且 ≥ 2016）平均 RPS 最小**的参数。2020、2021 保留在窗口内（与回测一致）。
- **选参数用的回放不带自适应收缩（τ 恒为 1）**，与 `fix.py` 一致：先用无收缩的 Elo 回放选出参数，
  再用选出的参数跑带自适应收缩的 V2 得到最终预测。不要在选参时同时启用 τ。
- 回放是确定性的，开销很小（毫秒到秒级），因此每次同步都**从 2014 年起整体重放**，不持久化评分状态。
- 参考：2026 年回测选出的参数为 `(K,H,s,c,gexp,reg,newstart) = (10, 60, 150, 0.7, 1.0, 0.8, 1450)`，
  用作验收夹具。

**自适应收缩 τ**

- 预测每场比赛前，用此前最近 150 场（不足 40 场则 τ=1）的 `(x, 实际结果)`，
  在 τ ∈ {0.3,0.4,…,1.2} 中选使对数损失最小者。
- τ 同时作为「把握度」信号：越小表示本赛季球队差距越小、预测越保守。

**基线**

同时记录此前所有非中立场地比赛的主平客频率（带 30 场、先验 0.46/0.26/0.28 的平滑），用于战绩对比。

## 数据

- 新增表保存历史比分，不修改 `f_i_matches`：`f_i_historical_matches`
  （`match_id` 主键、`season`、`match_date`、`match_time`、`home_team_id`、`away_team_id`、
  `home_score`、`away_score`、`neutral` 布尔）。2014–2025 共约 2800 场，
  由一次性命令从新浪回填（`SinaCslClient.fetch_round_matches`，逐轮、逐赛季，请求间留间隔）。
- 回放时的比赛序列 = 历史表 ∪ `f_i_matches` 中已结束且 `source_active` 的比赛，按日期时间排序；
  2020、2021 的 `neutral` 为真。重复的 `match_id` 以 `f_i_matches` 为准。
- 回填后必须做数据校验：每赛季场次（240，2020=160，2021=176，2022=306）、无重复 `match_id`、
  比分均有值。校验失败拒绝写入。
- 球队改名不影响结果：全程使用 `team_id`。

## 预测的存储与冻结

新增表 `f_i_match_outlooks`（迁移时间戳须大于现有最新迁移；迁移不随部署自动执行，由负责人在 peiqian 手动执行）：

- `match_id` 主键，引用 `f_i_matches.match_id`
- `home_win`、`draw`、`away_win`（模型概率，和为 1）
- `baseline_home`、`baseline_draw`、`baseline_away`（生成时的基线概率）
- `tau`（把握度系数）、`model_version`（如 `elo-v2`）、`params`（JSONB，所用滚动参数）
- `generated_at`、`kickoff_at`
- 赛后字段：`outcome`（0/1/2）、`rps_model`、`rps_baseline`、`scored_at`

规则：

1. 每次同步结束后，为所有**尚未开赛**的比赛重新计算并 upsert（赛程变更、评分变化都会更新）。
2. **开赛后冻结**：`now >= kickoff_at` 的比赛不得再被更新或覆盖，数据库层用条件更新保证
   （`WHERE kickoff_at > now()`），不仅靠应用层。`kickoff_at` 来自当前赛程（北京时间）。
3. 比赛结束后，计分任务写入 `outcome`、`rps_model`、`rps_baseline`、`scored_at`；已计分的行不可再改。
4. 比赛改期：若尚未开赛，按新时间重新生成；若旧时间已过且已冻结，则保留原冻结记录并在 `params` 中标注，
   不得静默改写。
5. 预测生成失败**不得**使同步事务失败或回滚；应记录错误并继续（预测是附加能力）。
6. 同步逻辑遵循现有 `team_insights.py` 的方式：在 Python 里预计算，写表；
   不要挪到后端或前端。入口放 `sina_csl_scraper` 内新模块，不修改洞察逻辑。

## 后端（只读）

Rust 后端只读取，不计算。按现有分层新增模块（`domain` / `ports` / `application` / `adapters`）：

- `GET /api/v1/live/match-outlook?match_id=…`：返回该场的三类概率、`tau`、是否已冻结、
  赛后则返回 `outcome`。无记录时返回明确的「暂无」，不报错。
- `GET /api/v1/live/match-outlook/record?season=…`：已计分比赛的汇总，包括场数、命中率
  （预测概率最大的结果是否发生）、平均 RPS（模型与基线）、模型较基线的 RPS 改善。
- 响应风格、缓存策略遵循现有 `/api/v1/live/**` 约定。后端不做任何概率计算。

## 小程序展示

**位置：洞察页（`pages/insights`）顶部**，在 `InsightsTeamPanel` 之前。洞察页本来就是放进球/助攻/失球贡献这类分析的地方，
用户预期一致；页面顶部只保留一处共用球队选择，统一控制概率与进失球贡献，默认选用户关注的球队（蓉城球迷默认蓉城）。
切换不重载整页：预测按比赛缓存 60 秒、合并在途请求并后台预取各队下一场，首次未缓存时只在保留尺寸的局部区域显示加载。
首页只做一个轻量入口（如下一场比赛卡片上的一行摘要，点击进入洞察页），不在首页完整展示，避免加重首屏。

**门槛（产品负责人已定）：**

- **不做会员专享。** 所有已登录用户可见，放在洞察页现有会员锁定面板（`membershipBenefitsLocked`）**之上**，不受其影响。
  预测的价值是留存与传播，且模型尚未经过完整赛季验证，现阶段收费会伤害信誉并阻断传播。
- 未登录：显示登录引导，与洞察页其他内容一致。
- 小程序审核期间：隐藏（遵循洞察页现有的 `systemConfigUnderReview` 逻辑，只显示基础内容）。
- **收费时机**：待战绩公开满一个完整赛季、数据证明稳定价值后再议，且只考虑对增值部分收费
  （详细归因拆解、历史预测完整查询等）；基础三段概率条和战绩始终免费。不得在现阶段加会员门槛。

具体版式由实现方参考现有视觉，遵守设计令牌和依赖边界（组件不引入 api，页面间不互相 import；跨页逻辑放 `src/utils`）。

内容：

1. **三段概率条**：主胜 / 平 / 客胜，数值取整百分比，和为 100%。
2. **简化说明**：按负责人后续界面指令，删除 τ 把握度解释与常规同步/冻结状态文案；τ 仍用于模型校准，接口字段保留。仅在赛程调整时提示保留的是原赛前记录。
3. **战绩入口**：展示赛季累计「命中 X/Y，较只看历史频率的基线提升多少」，并如实展示不佳的数据。
4. **说明文案**：「基于历史比赛结果的统计模型，仅供球迷参考，不代表比赛结果。」

措辞约束：

- 禁止出现：赔率、盘口、投注、下注、推荐、稳、必中、保证。
- 不展示比分预测，不突出单一「推荐结果」。
- 预测蓉城落败时的表述同样中性，不做特殊处理，也不做针对性突出。
- 样本不足（本赛季已赛场次很少）时标注「赛季初，参考价值有限」。

## 隐私与合规

- 不收集任何个人信息；本功能与用户账户无关。
- 不引入任何博彩数据源。若后续有人提议加入赔率作为特征或对照，须回到负责人处重新评估，不属本设计范围。

## 验收标准

1. **复现回测**：用同一份历史数据，生产实现的 V2 在 2019–2026（剔除 2020–21）上
   RPS 与 `research/match_outlook/fix.py` 的结果相差不超过 0.0005（约 0.1988），
   2026 年选出的参数为 `(10, 60, 150, 0.7, 1.0, 0.8, 1450)`。
2. **无前视**：测试证明任意一场比赛的预测只依赖其之前的比赛；打乱之后比赛的比分，不应改变该场预测。
3. **冻结**：对已开赛的比赛重复运行生成，数据库中的概率、`generated_at` 不变；
   用生成任务的条件 upsert 尝试更新已冻结行应被拒绝；按负责人后续指令，不增加拦截无条件直接 UPDATE 的防御性触发器。
4. **计分**：比赛结束后写入 `outcome` 和 RPS，与手算一致；重复运行不改变已计分的行。
5. **失败隔离**：模拟预测计算抛错，原有同步仍然成功并提交。
6. **数据校验**：各赛季场次、重复 `match_id`、缺失比分均有测试。
7. **概率合法**：每条预测三类概率非负、和为 1。
8. **后端**：两个接口有正常、无记录、非法参数的测试；确认不含任何概率计算。
9. **前端**：措辞黑名单有自动化测试（页面文案不得包含禁用词）；
   `bun run type-check`、`bun test`、`bun run check:boundaries`、`bun run verify:mp-components` 通过。
10. 通过：`cargo test`；抓取器 `uv run pytest`。

## 未纳入（有意不做）

- **泊松模型 / 与 Elo 取平均**：泊松与 Elo 差异不显著，取平均只带来很小的统计改善，
  首版不增加复杂度。若后续要做，须先在滚动调参下重新回测。
- **技术统计特征**：当前技术统计来自雷速，历史赛季能否取得未验证；这只影响后续模型改进，不影响首版。
- **预测公开榜单、用户竞猜**：另议。涉及现金或实物奖励的玩法不在讨论范围，且有合规风险。
