# 学员功能

用户要求将我的页邮箱卡片改为“学员功能”入口，入口及目标页沿用现有审核开关，审核模式不展示服务。二级页面保留邮箱编辑，提供证书续期（99 元/年）和工具升级（699 元/套），小程序内支付、负责人线下交付。微信联系二维码存 MinIO，服务说明由 Web 管理后台设置。

## 界面与配置

- 我的页显示学员功能导航卡，登录且非审核模式才可进入。
- 学员页上部显示联系微信二维码，支持预览；接着是两项服务、当前账号购买记录及邮箱设置。支付成功必须由后端查单确认；取消、待确认和退款分别显示。
- Web 后台新增学员功能配置：两项说明、微信联系二维码 HTTPS 地址、已发布微信支付商品 ID、启用开关。名称、99/699 价格与计费单位固定，和会员商品独立；说明可留空保存草稿，开放购买前必须有说明、二维码和商品 ID。
- 二维码文件不打包进小程序；本次按用户指定来源上传 MinIO，使用版本化对象名并回读校验。

## 接口

- `GET /api/v1/student/config` 用户 JWT，返回 `{contact_qr_url,services:[{code,title,description,price_cents,unit,enabled}]}`。
- `POST /api/v1/student/orders` 用户 JWT，body `{code}`；返回现有 `{order_no,params}` 支付协议，金额由服务端固定校验。
- `GET /api/v1/student/orders?page=1&page_size=20` 用户 JWT，返回 `{items:[{order_no,code,title,amount_cents,status,paid_at,created_at}],total,page,page_size}`；仅当前账号，支持重进页面查找已付及待确认订单。
- `GET/PUT /api/v1/admin/student/config` 管理员 ManageProducts 权限；配置结构同上，每项另有 `product_id`，PUT 提交完整配置。
- code 仅 `certificate_renewal`、`tool_upgrade`；单位 `年`、`套`；服务商品类型 `student_service:<code>`，映射键追加 `@9900`/`@69900`。

## 实现边界

新增 student 六边形模块。配置存既有系统配置 JSON，管理写入同时事务同步支付商品映射和审计；产品 ID 缺失或未启用不允许发起付款。扩展现有虚拟支付商品键约束、查单/回调的服务订单结算及退款分支；服务支付只记录付款，不授予或修改会员等级、不推断线下交付完成。付款通知的金额、身份、平台交易号、重复通知和退款处理继续使用既有链路。

本次不执行真实收费，不自动生产迁移、部署、上传。后台写验证使用隔离数据库。用户提供的 IMG_0715.JPG 已原样上传 MinIO，迁移以该地址初始化配置且两项购买均停用，不覆盖已有配置；微信已发布商品 ID 由后台配置。
