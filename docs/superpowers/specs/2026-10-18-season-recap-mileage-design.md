# 赛季总结（里程海报）设计

日期：2026-10-18
状态：待实现（设计由 Claude 与产品负责人讨论后撰写）

## 背景与目的

产品要深耕成都蓉城球迷社区。蓉城客场远征多由球迷会组织、客场票每次用完，球迷分享欲强，
但没有产品化的「成果」可以分享。赛季总结海报让球迷把一整年的投入变成可以发朋友圈、抖音的图，
海报带小程序码，成为免费的拉新入口。

**这是传播和留存功能，不是收费功能。** 不要给海报加付费门槛，否则分享会减少。

## 时间约束

2026 赛季最后一场比赛在 **2026-11-08**（`f_i_matches` 中 season=2026 最大 `match_date`）。
最好在赛季结束前上线，赛季结束后一到两周内是分享高峰。需要尽量小的首版。

## 目标

1. 用户勾选自己去过的蓉城比赛（主场、客场）。
2. 用户填写一次「去主场的单边大概距离（公里）」。
3. 生成一张海报，核心是两个数字：**客场里程**、**主场里程**，另有场次数、城市数。
4. 海报带小程序码，携带来源参数 `src=share`（见《用户来源追踪设计》），以便统计由分享带来的新用户。

## 非目标

- 不做里程排行榜、勋章榜、好友对比。
- 不做凭票验证，勾选以用户自报为准。
- 不采集用户定位。
- 不做其他球队的版本，只服务成都蓉城。
- 不做付费功能。

## 反目标

- 勾选或填写流程繁琐到用户放弃。目标：从进入到看到海报不超过约 30 秒。
- 里程算错且无法解释。
- 海报生成失败时页面无反馈。

## 口径（产品负责人已确认）

- **客场里程**：每场客场 = 成都 → 对手所在城市的**球面（大圆）直线距离** × 2（往返）。
  所有用户口径统一，不由用户输入。
- **主场里程**：用户填写的单边距离 × 2（往返）× 已勾选的主场场次数。
- 总里程 = 客场里程 + 主场里程，海报上主场、客场**分别**展示。
- 四川没有其他中超球队，不存在同城对手，无需特殊处理。

## 数据

### 球队 → 城市对照

`f_i_matches` 与 `f_i_teams` **没有城市字段**。需要一份球队城市与经纬度对照，共 16 支球队
（来自当前 `f_i_teams`）：

北京国安、青岛海牛、上海申花、天津津门虎、山东泰山、河南队、浙江队、云南玉昆、
大连英博、重庆铜梁龙、辽宁铁人、上海海港、成都蓉城、深圳新鵬城、武汉三镇、青岛西海岸。

注意：

- 青岛海牛、青岛西海岸同城；上海申花、上海海港同城。
- 各队主场所在城市由实现方核对（例如山东泰山为济南、河南队为郑州、辽宁铁人为沈阳、
  浙江队为杭州、云南玉昆为昆明），不要凭队名猜测，需逐队确认。
- 经纬度取城市中心即可，不需要精确到球场。
- 对照表建议放在代码里的常量表或一份迁移种子数据，由实现方决定；队伍很少，不要做后台管理界面。
- 小程序内已有 `src/utils/stadiumRegions.ts`，实现前先看是否可复用。

### 用户数据

新增存储（迁移时间戳须大于现有最新迁移；迁移不随部署自动执行，需要在 peiqian 手动执行）：

- 用户已勾选的比赛：`user_id`、`match_id`（引用 `f_i_matches.match_id`）、`created_at`，
  `(user_id, match_id)` 唯一。
- 用户主场单边距离：每用户一个数值（公里），建议限定合理范围（如 0–500），超出视为非法输入。

勾选是否需要云端保存：建议保存，便于换设备和后续做统计。如果实现方认为首版仅本地存储更快，
可以说明理由，但需和产品负责人确认。

## 计算位置

里程计算放在后端 `application` 层，前端只展示结果，避免前后端口径不一致。
遵循项目分层（`domain` / `ports` / `application` / `adapters`），不要写在 web handler 或 SQL 里。
距离用球面距离公式，计算结果取整到公里。

## 交互

1. 入口放在合适的位置，如「我的」页或赛季结束提示，由实现方参考现有页面选择；
   页面之间不能互相 import，复用逻辑放 `src/utils`、组件放 `src/components`。
2. 步骤一：列出本赛季蓉城的比赛（主客场区分），用户勾选已去过的；仅展示已结束的比赛。
3. 步骤二：首次填写主场单边距离，之后记住。
4. 生成海报：展示客场里程、主场里程、场次数、城市数，带小程序码。
5. 海报保存到相册，支持分享。保存到相册需要用户授权，被拒绝时给出提示。

海报的视觉设计由实现方参考现有小程序风格，主角是里程数字。

## 边界情况

- 没有勾选任何客场：客场里程为 0，海报不显示空的客场栏，或明确显示「本赛季尚未远征」。
- 没有填写主场距离：不能生成主场里程，提示用户填写，或在海报上省略主场部分。
- 比赛被改期或取消（`source_active=false`）：不应再出现在可勾选列表中；已勾选的需要有定义好的处理。
- 用户在赛季结束后回来：仍可查看海报。

## 验收标准

1. 勾选若干客场后，客场里程等于各城市大圆距离 × 2 之和，可用已知两城距离人工核对。
2. 主场里程等于单边距离 × 2 × 勾选的主场场次。
3. 重复勾选同一场比赛不会重复计入。
4. 距离输入非法（负数、超范围、非数字）被拒绝并有提示。
5. 海报能生成、保存，扫码进入后来源参数为 `src=share`。
6. 通过测试：后端 `cargo test`；小程序 `bun run type-check`、`bun test`、
   `bun run check:boundaries`、`bun run verify:mp-components`。
