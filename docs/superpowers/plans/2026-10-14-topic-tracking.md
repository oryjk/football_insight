# 动态球队新闻采集与话题追踪

用户已确认：每次任务按当前赛季排名选中超前三/后三、中甲前二；全文筛选，不要求列表标题出现球队；查询快照不参与新闻新旧判断；文章多球队标签，详情中按球队查看当前话题之前的时间线。

1. Python：独立 scope 模块读取并校验两个联赛的完整积分榜，保存运行时名单；球名/简称匹配采用足球上下文，完整名单供对手标签识别。列表宽召回，正文验证，按近期窗口与已发布链接去重，删除全局时间水位限制。生成批次沿用兼容的 77680 归属；每篇新增 team_tags，以 ID 为稳定标识。日志记录候选及跳过原因。
2. Rust：标签作为可选 JSONB 字段，无新表；独立 timeline query/port，绑定球队标签、当前话题锚点和分页游标，查询锚点之前的同标签文章，不改变旧历史接口语义。标签名与稳定 ID 返回详情/首页/历史；热度继续按原批次归属统计。
3. 小程序：详情标签可点击，展示时间线、切换球队、重试及加载更多，按北京时间显示日期；删除详情/历史的写死蓉城说明。使用已有 token 与跨端组件。
4. 兼容历史：独立显式补标签命令只更新 team_tags，保留文章 ID、正文、音频、热度、发布时间。默认不写生产。发布前须核对标签及新接口，避免旧后端忽略标签。
5. 验证：Python 排名动态变化/缺失/别名/正文匹配/去重/快照/生成来源；Rust HTTP 与隔离 PostgreSQL 的标签分页/锚点/游标串用/旧数据；前端映射、类型、全套测试、H5 与微信构建。修改后端后启动新本地验证进程；生产部署状态单独报告。

工作区使用原生 managed worktree，避免本机 cron 执行未完成的代码。既有用户未提交改动不纳入提交。
