# Football Insight Android 管理端设计规范（评审稿）

## 1. 当前判断

当前 App 已有基础 Material 3 浅色色板，但还不是完整设计系统：

- 已定义主色、次色、辅助色、错误色和部分背景色
- 未完整定义 `on-*`、container、outline variant 等配对颜色
- 未定义成功、警告、信息、禁用等业务语义色
- 字体、间距、圆角、列表密度和组件状态仍主要使用 Material 默认值
- 暂无深色主题策略

本规范建议保留当前绿色方向，补齐设计 token 和使用边界，不进行营销化或装饰性改版。

## 2. 设计目标

- 定位：面向管理员的高频操作工具，优先扫描效率、信息对齐和操作可预期性
- 气质：克制、可靠、清晰，保留足球产品识别，但不使用大面积球场绿
- 密度：以列表和分区为主，不把页面区块包装成层层卡片
- 可访问性：普通正文和背景对比度至少达到 WCAG AA；状态不能只靠颜色表达
- 一致性：业务页面禁止直接写 `Color(...)`，只使用主题或业务语义 token

## 3. 核心色板

### 品牌与功能色

| Token | 色值 | 角色 | 使用范围 |
| --- | --- | --- | --- |
| `primary` | `#176B52` | 主色，深草绿 | 主要按钮、选中导航、可点击姓名、关键图标 |
| `onPrimary` | `#FFFFFF` | 主色前景 | 主按钮文字和图标 |
| `primaryContainer` | `#D6F1E6` | 主色浅容器 | 已选筛选项、轻量选中态 |
| `onPrimaryContainer` | `#0A3B2D` | 主色容器前景 | 选中态文字和图标 |
| `secondary` | `#4D5F6D` | 次色，蓝灰 | 次级信息图标、结构性辅助操作 |
| `secondaryContainer` | `#E1E8ED` | 次色浅容器 | 中性标签、非关键状态 |
| `onSecondaryContainer` | `#263740` | 次色容器前景 | 中性标签文字 |
| `tertiary` | `#9B5C17` | 辅助色，琥珀 | 会员权益、需注意但非错误的信息 |
| `tertiaryContainer` | `#FFE0B7` | 辅助色浅容器 | 高会员等级、提醒背景 |
| `onTertiaryContainer` | `#5A3300` | 辅助容器前景 | 会员和提醒文字 |

### 中性色

| Token | 色值 | 使用范围 |
| --- | --- | --- |
| `background` | `#F7F8F5` | 页面背景、顶部应用栏 |
| `onBackground` | `#18211D` | 页面主文字 |
| `surface` | `#FDFEFB` | 底部导航、弹窗、输入区域 |
| `onSurface` | `#18211D` | Surface 主文字 |
| `surfaceVariant` | `#E8ECE7` | 筛选区、轻量分组背景 |
| `onSurfaceVariant` | `#58635D` | 标签、时间、说明文字 |
| `outline` | `#747A75` | 输入框边界、弱提示 |
| `outlineVariant` | `#C8CEC9` | 分割线、非强调边界 |

### 业务语义色

| 语义 | 主色 | 浅容器 | 使用规则 |
| --- | --- | --- | --- |
| 成功 / 正常 | `#2E6B3C` | `#D9EEDC` | 正常状态、操作成功；同时显示文字或图标 |
| 信息 | `#336A86` | `#D8EAF3` | 同步状态、普通系统信息 |
| 警告 | `#9B5C17` | `#FFE0B7` | 到期提醒、需关注状态 |
| 危险 / 错误 | `#B3261E` | `#F9DEDC` | 禁用、删除、请求错误；不得用于普通强调 |
| 禁用 | `#8A918C` | `#ECEFEB` | 不可操作控件和禁用用户的弱化信息 |

## 4. 颜色使用规则

- 同一屏幕只允许一个视觉上最强的主操作使用 `primary`
- `tertiary` 只表达会员和提醒，不作为通用按钮颜色
- 禁用、恢复等状态必须同时使用图标或文字，不能只改变颜色
- V9 到 V1 筛选统一使用主色选中态，不为九个等级分别制造彩虹色
- V9、V8、V7 可在详情中的会员标签使用琥珀容器；其余等级使用中性容器
- 页面背景以中性色为主，品牌绿不超过首屏视觉面积的约 20%

## 5. 字体规范

首版继续使用 Android 系统无衬线字体，避免增加字体包体和中文字体兼容风险。

| 层级 | 建议规格 | 使用位置 |
| --- | --- | --- |
| 页面标题 | 22sp / 28sp / Semibold | 顶部应用栏、登录标题 |
| 区块标题 | 14sp / 20sp / Semibold | 账号、会员、邀请下级等分区 |
| 正文 | 14sp / 20sp / Regular | 列表主信息、详情值 |
| 辅助文字 | 12sp / 16sp / Regular | 时间、数量、说明、状态 |
| 按钮文字 | 14sp / 20sp / Semibold | 主要和次要命令 |

规则：

- 不使用负字距，字距保持 `0`
- 姓名最多一行，超长使用省略号
- 时间、金额、订单号等需要纵向比较的数据使用等宽字体并固定对齐
- 不随屏幕宽度缩放字号，响应式变化通过布局完成

## 6. 间距、尺寸与圆角

- 基础间距单位：`4dp`
- 常用间距：`4 / 8 / 12 / 16 / 24 / 32dp`
- 页面水平边距：`16dp`
- 列表行最小高度：`48dp`
- 图标按钮触控区域：`48 x 48dp`
- 常规图标：`24dp`
- 主按钮高度：`48dp`
- 输入框最小高度：`56dp`
- 按钮和输入框圆角：`6dp`
- 弹窗和独立重复项圆角：`8dp`
- 页面区块不使用悬浮卡片；用留白、标题和分割线建立层级

## 7. 组件规范

### 顶部应用栏

- 背景使用 `background`
- 标题使用 `onBackground`
- 返回、刷新等图标使用标准 48dp 触控区域
- 详情页始终提供顶部返回，并接入 Navigation Compose 系统返回栈

### 底部导航

- 背景使用 `surface`
- 选中项使用 `primary` 或 `primaryContainer`
- 未选中项使用 `onSurfaceVariant`
- 只放置同级一级目的地，不放业务操作按钮

### 筛选项

- 使用 `FilterChip` 单选状态
- 选中态使用 `primaryContainer + onPrimaryContainer`
- 多于一行容量时横向滚动，控件高度不能因选择而变化
- 状态筛选与会员等级筛选分别成组，但允许组合查询

### 用户列表

- 姓名是主信息，账号和会员等级是次信息，状态在尾部
- 正常状态使用成功语义；禁用状态使用危险语义并带文字
- 整行或明确的“查看与管理”命令进入详情，触控区域不小于 48dp

### 详情分区

- 分区标题使用 `primary`
- 标签使用 `onSurfaceVariant`，值使用 `onSurface`
- 可点击姓名使用 `primary`，同时保留点击反馈
- 对比型数据采用固定列宽；长文本省略，不允许覆盖相邻内容

### 危险操作

- 禁用用户等操作使用错误色，并在确认弹窗中要求填写原因
- 恢复用户属于纠正操作，使用主色或成功色，不沿用错误色
- 主操作和危险操作不得使用相同视觉权重并排混淆

## 8. 主题范围

首版建议明确只支持浅色主题：

- 原因：当前是内部管理工具，先确保浅色高密度信息和状态对比一致
- Android 系统切换深色时仍保持受控浅色主题，避免半套深色产生不可读组合
- 后续增加深色主题时，必须一次性补齐所有 Material 3 color role 和语义色，不做局部反色

## 9. 实施建议

确认本规范后再分两步落地：

1. 建立 `AdminColorTokens`、完整 `lightColorScheme`、Typography 和 Shapes，消除页面硬编码样式。
2. 按登录、用户列表、用户详情、审计、设置的顺序做组件视觉回归和真机截图验收。
