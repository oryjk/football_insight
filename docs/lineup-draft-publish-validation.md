# 战术板云端草稿与显式发布验证

日期：2026-10-19。设计见 [spec](superpowers/specs/2026-10-19-lineup-draft-publish-design.md)。

## 结果

- 每用户每球队一份云端私密草稿，保存允许 0–11 人。公开版本继续使用原记录；只有发布入口要求满 11 人并更新公开快照。
- 发布与旧版保存入口通过同一 repository 原子事务同步私密草稿；存草稿只写私密表，公开分享码、点赞、创建时间不变。旧 GET/PUT 保持兼容。
- 前端四个操作均带线性图标；发布/更新发布沿用居中确认，草稿仅轻提示；分享只读取明确发布的快照，不隐式保存或发布。
- 本机稿按账号隔离；只有登录恢复明确触发的游客意图会移交游客稿，旧 autosave 标记只存私密草稿。保存期间的新编辑、切队/切账号后的迟到结果均受上下文保护。

## 验证

- 前端 `bun test`：1200 通过、0 失败。类型和 import 边界通过；H5、微信构建和小程序组件注册通过。
- 后端 `cargo test`：599 通过、92 默认忽略；其中 19 项阵容 SQL 测试已在独立 PostgreSQL16 的 `football_lineup_draft_test` 执行通过，未写生产测试账号或阵容。`cargo check`、修改文件格式检查通过。
- SQL 覆盖私密草稿不改变公开/点赞/创建时间、首次和再次发布的事务失败回滚、迁移回填且不覆盖已有草稿；应用与 HTTP 覆盖授权、旧接口及发布满员要求。
- 320×568、375×667、390×844、430×844 浏览器真实页面与 mock API 验证：操作区一屏可达；存稿不公开；取消发布无写入；连续确认只发布一次；更新发布保留分享码；分享无写入；另一设备的不满员草稿可恢复且不影响满员公开版本。
- 独立复核发现后台登录在游客页面加载中/后完成时，旧身份上下文使保存返回 cancelled；页面现监听有效身份变化并重新装载当前球队，普通后台登录不移交游客稿。
- 全仓严格 Clippy 与 Rust 架构扫描仍命中其他未修改模块的既存问题，lineup 无命中；未扩大重构。
